Plan in one thread, ship reviewed PRs

A workflow for T3 Code: you plan with one orchestrator session, and background workers implement, review and merge each task as a GitHub pull request.

Install it

Free and open source · MIT · Python 3.11+

Four roles, one you talk to

You talk to one session, the orchestrator. The rest runs in the background as T3 delegated tasks, and every task ends as one pull request, reviewed at an exact commit.

The orchestrator plans the work with you and reports back. It edits nothing: its hook lets it run only t3-workflow, so every change reaches your code through a worker and a pull request. It runs on any Claude or Codex model you pick in T3.

An implementer takes one task in its own T3 checkout, changes only that task’s paths, runs the project’s checks and opens one pull request. Review notes, conflicts and CI failures come back to the same implementer. By default, GPT-6.1-Sol at xhigh.

A reviewer reads the pull request at one commit and changes nothing. It approves that exact commit with the t3/review status, or lists each blocking finding with its file and line. By default, Sonnet 5.5 at xhigh.

DevOps brings each confirmed pull request up to date, waits for CI and squash-merges it through GitHub. It owns the pipeline too, and fixes it in PRs of its own. Turn it off and the workflow merges with no model. By default, Opus 5.5 at xhigh.

Beforeyou install

What do I need before I install it?

Python 3.11 or newer, uv (or pipx), Git, the GitHub CLI signed in, and T3 Code with Claude, Codex or goose signed in. The orchestrator runs on Claude Code or Codex, so one of them must be on your PATH.

Does it work on macOS and Linux?

It has only been tried on Windows so far. On macOS the watcher starts as a LaunchAgent, and on Linux as a systemd user unit. Both are covered by tests, not yet by a real login, and reports are welcome.

Can a worker push straight to main?

No. Setup protects the branch: a pull request is required, with the CI checks and t3/review green on an up-to-date branch, admins included, and no force-push. DevOps merges only through worker merge, which squash-merges exactly the approved commit.

Do I have to use the DevOps worker?

No. Turn it off at setup, or later with “use t3 workflow: turn DevOps off”. The workflow then updates each confirmed pull request, waits for CI and merges it itself, with no model. Every CI failure goes back to the implementer.

Which models do the workers use?

You choose each role’s model and effort, separately, at setup or later. For what you leave open, Jev may advise an implementer’s or reviewer’s model. Otherwise the defaults apply: GPT-6.1-Sol for implementers, Sonnet 5.5 for reviewers and Opus 5.5 for DevOps, each at xhigh. Setup checks which models your T3 can run.

What is Jev, and do I need it?

Jev is an optional model advisor. Put a TypeSafe key on one line in ~/.t3-workflow/secrets/typesafe-api-key.txt, or set TYPESAFE_API_KEY. Without it, every task uses the models you chose or the defaults.

What does the installer change on my computer?

Hooks in Claude Code’s and Codex’s settings, a marked block in CLAUDE.md and AGENTS.md, goose models in T3’s settings, and a watcher that starts when you log in. Every file it edits is backed up first, and t3-workflow uninstall removes it all.

Does it take over every session?

No. The workflow is opt-in: it runs only when your message says “use t3 workflow”, and in the orchestrator’s own wakes. Any other message gets an ordinary answer, even in a bound thread.

My project has no CI yet. Can I still use it?

Yes. CI becomes the first plan: one task adds the pull-request workflow, and its job name becomes the required check. Deployment waits on standby until you name a server.

Install it,say the words

Two commands install it. Then, in a T3 project on GitHub, say “use t3 workflow: set up this project”, and that session becomes the orchestrator, paused until you activate it.

>_Terminal
  1. uv tool install git+https://github.com/Mahmoud6901/t3-event-workflow
  2. t3-workflow install

Installed. Quit and reopen T3 Code.

Then, in a T3 project on GitHub

use t3 workflow: set up this project
